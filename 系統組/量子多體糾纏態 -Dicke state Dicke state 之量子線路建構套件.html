這個專題在做什麼

開發產生 Dicke state 的量子線路套件。Dicke state 是固定激發數下所有計算基底排列的等幅疊加，常用於量子資訊與多體糾纏研究；工作重點是線路合成、正確性與閘數／深度。

擬議摘要

本專題旨在處理以下問題：開發產生 Dicke state 的量子線路套件。Dicke state 是固定激發數下所有計算基底排列的等幅疊加，常用於量子資訊與多體糾纏研究；工作重點是線路合成、正確性與閘數／深度。 研究方法將依序定義 qubit 數、激發數與 API；接著實作一種或多種 Dicke state 線路建構法；接著以模擬器驗證態保真度並比較閘數、深度與硬體限制。實驗應採固定資料切分或測試情境，將提出的方法與可重現的簡單基準比較，同時記錄主要品質指標、執行成本與失敗案例。預期成果包括可執行的端到端原型、可重建的實驗結果，以及對方法適用條件與限制的分析。

關鍵詞： 量子計算、量子演算法、計算複雜度、軟體測試

必修課程逐科主題與選題前檢核

程式設計（Python 或 Java/C++）

  • 應掌握的具體主題：變數、型別、控制流程與函式；模組化、例外處理與檔案 I/O；基本物件導向、套件管理、除錯與單元測試；Git 版本控制與可重現執行環境。
  • 選題前檢核：能從零完成一個讀取真實資料、處理錯誤、輸出結果且附測試的小程式。

資料結構

  • 應掌握的具體主題：陣列、鏈結串列、堆疊與佇列；雜湊表、樹、堆積與圖；走訪、搜尋、排序與記憶體／時間取捨；依資料存取模式選擇結構。
  • 選題前檢核：能解釋選用某資料結構的原因，並估算主要操作的時間與空間複雜度。

演算法

  • 應掌握的具體主題：漸近複雜度與正確性證明；分治、貪婪、動態規劃與回溯；圖搜尋、最短路徑、匹配與基本最佳化；建立基線、比較演算法與設計測試案例。
  • 選題前檢核：能為核心問題提出至少兩種方法，說明複雜度並用邊界案例驗證。

線性代數

  • 應掌握的具體主題：向量、矩陣、內積與範數；線性轉換、特徵值／特徵向量；矩陣分解、最小平方法與降維；張量形狀、批次運算與梯度中的矩陣微分概念。
  • 選題前檢核：能手算小型矩陣運算，並用 NumPy 解釋模型輸入、權重與輸出的形狀。

離散數學

  • 應掌握的具體主題：集合、關係、函數與邏輯；證明方法、遞迴與歸納；排列組合、圖論與樹；有限狀態、布林代數與離散機率。
  • 選題前檢核：能把問題形式化成集合／圖／狀態機，並對小規模案例驗證性質。

建議工具能力

選題判斷

  • 預估難度：很高
  • 適合的學生：數學基礎強、喜歡演算法與前沿計算的學生。

  • 線路深度隨 qubit 增長快速上升

詳細完成步驟

以下以一個 16–18 週學期專題規劃；需要人體研究、特殊硬體、臨床／產業資料或長期蒐集者，應在第 1 階段就延長時程。各階段都要留下可重現的程式、設定與結果。

  1. 第 0–1 週：與教授鎖定問題與邊界。 把題目改寫成一頁規格，明確列出使用者、輸入、輸出、不處理事項、成功指標與失敗條件。面談必須決定：套件目標框架、API 與支援的 n/k 範圍為何？ 評估重點是理論閘數、模擬效能還是真機結果？
  • 完成門檻：教授確認書面 scope、可用資源、每位組員分工及倫理／授權限制。
  1. 第 1–3 週：通過先備能力檢核。 不只「修過」課，而要完成下列可展示的小任務：
  2. 完成「程式設計（Python 或 Java/C++）」的選題前檢核
  3. 完成「資料結構」的選題前檢核
  4. 完成「演算法」的選題前檢核
  5. 完成「線性代數」的選題前檢核
  6. 完成「離散數學」的選題前檢核
  • 完成門檻：把檢核成果放入同一個 Git repository，其他組員能依 README 重跑。
  1. 第 2–4 週：閱讀與基準盤點。 找 3–5 個最接近的方法、資料集或開源系統，整理它們的輸入、輸出、限制、授權與評估方式。先決定一個最簡單、可重現的 baseline，避免一開始直接做最複雜模型。
  • 完成門檻：一張方法比較表、一份引用清單，以及 baseline 的選擇理由。
  1. 第 3–6 週：建立資料／設備／環境。 以 Python、Qiskit/Cirq、Statevector simulator、Optional GPU 建立固定版本環境；準備最小資料樣本、資料字典、切分規則與設備清單。若涉及個資、人體、醫療、攻擊或平台內容，先完成同意、去識別、隔離與授權程序。
  • 完成門檻：新電腦可依腳本建立環境，並從原始輸入跑到一筆可檢查的輸出。
  1. 第 4–7 週：完成端到端 baseline。 用最簡單可行方法串起輸入、處理、輸出與評估；先記錄速度、資源與主要品質指標，這會是後續改進的比較基準。
  • 完成門檻：固定測試集上的第一份結果表、至少 10 個人工檢查案例，以及已知失敗清單。
  1. 第 6–12 週：實作題目核心。 依序完成：
  2. 定義 qubit 數、激發數與 API
  3. 實作一種或多種 Dicke state 線路建構法
  4. 以模擬器驗證態保真度並比較閘數、深度與硬體限制
  • 每完成一項就加自動測試、實驗設定與中間產物版本；若兩週沒有勝過 baseline，立即縮小範圍或改方法。
  1. 第 10–14 週：做公平而可重現的評估。 以「以模擬器驗證態保真度並比較閘數、深度與硬體限制」為主軸，預先固定資料切分、主要／次要指標與比較方法；加入 ablation、效率量測、信賴區間或重複實驗，並按場景切片做錯誤分析。
  • 完成門檻：baseline 與最終方法使用相同測試條件，結果表可由單一命令重建。
  1. 第 13–15 週：壓力測試與處理風險。 至少逐項完成：
  2. 針對「量子基礎學習曲線陡峭」建立驗證／檢核方式、緩解措施與停止條件
  3. 針對「線路深度隨 qubit 增長快速上升」建立驗證／檢核方式、緩解措施與停止條件
  4. 針對「模擬器可驗證的 qubit 數有限」建立驗證／檢核方式、緩解措施與停止條件
  • 完成門檻：每個高風險項都有證據、緩解方式及仍未解決的限制；不得把未知或無效結果隱藏。
  1. 第 15–17 週：整合成可示範成果。 建立從輸入到輸出的固定 demo 腳本，加入錯誤訊息、日誌、逾時／回復與最小操作介面；找未參與開發者照說明操作一次。
  • 完成門檻：5–10 分鐘穩定 demo、備用錄影，以及無網路／模型失敗／裝置斷線時的降級方案。
  1. 第 17–18 週：交付與答辯。 清理 repository，補齊 README、架構圖、資料卡／模型卡、安裝腳本、測試、實驗結果、限制、倫理聲明、簡報與海報；確認不可公開的資料與金鑰未被提交。
  • 完成門檻：另一位同學能依文件重現核心結果，團隊能用一張表回答「比 baseline 好多少、代價是什麼、在哪些條件會失敗」。
